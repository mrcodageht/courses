Créer et exécuter votre premier workflow

Comme nous l'avons vu, GitHub Actions utilise la syntaxe YAML pour définir les workflows. Chaque workflow est stocké en tant que fichier YAML distinct dans votre dépôt de code, dans un répertoire nommé .github/workflows.

C'est exactement à cet endroit que se crée le fichier /.github/workflows/main.yml lorsque vous avez cliqué sur Skip this and set up a workflow yourself.

Voici notre premier workflow avec un seul job et une seule étape :

name: Mon premier workflow
on: [push]
jobs:
  say-hello:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Hello, World!"

Appuyez sur le bouton Commit changes...

Votre fichier de workflow simple est maintenant dans votre dépôt et s'exécutera automatiquement à chaque push.

Maintenant, décomposons le fichier YAML pour comprendre ce qu'il fait :

name: Mon premier workflow

Ceci est le nom du workflow, qui apparaîtra dans l'onglet Actions de votre dépôt GitHub.

on: [push]

Ceci indique que le workflow sera déclenché à chaque événement push vers le dépôt.

jobs:

Définit le groupe de jobs à exécuter. Dans notre cas, il y a un seul job appelé "say-hello".

say-hello:

Ceci est le nom du job.

runs-on: ubuntu-latest

Spécifie que le job sera exécuté dans un conteneur avec la dernière version d'Ubuntu disponible.

steps:
Liste des étapes à exécuter au sein de ce job.
- run: echo "Hello, World!"

Cette étape exécute simplement la commande echo pour afficher le message "Hello, World!".

 

Visualiser les exécutions

Pour voir l'historique des exécutions, cliquez de nouveau sur Actions.

Vous aurez en un coup d’œil les informations suivantes pour les exécutions :

  • Nom du worflow
  • Fichier source du workflow
  • Statut de l'exécution : en cours, réussie ou échouée.
  • Message et SHA du commit relatif à l'exécution (ici Create main.yml).
  • Nom de la branche (ici main).
  • Temps écoulé depuis l'exécution (ici 5 minutes ago).
  • Durée de l'exécution (ici 13s).

Si vous cliquez vous aurez une vue summary avec à peu près les mêmes informations et une visualisation pour chaque job exécuté (certains jobs peuvent avoir réussi et d'autres échouer).
