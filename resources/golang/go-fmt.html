6. Formater le code avec go fmt

Garder un code propre avec go fmt

Dans n'importe quel projet de développement, surtout en équipe, une question revient sans cesse : comment doit-on formater notre code ? Faut-il utiliser des tabulations ou des espaces ? Où placer les accolades ? Ces débats, souvent appelés "guerres de style", peuvent faire perdre un temps précieux et créer des frictions inutiles.

L'équipe de Go a observé ce problème dans d'autres langages et a décidé de le résoudre de manière radicale et définitive.

Ils ont créé un outil officiel, go fmt (abréviation de "format"), qui analyse et réécrit votre code pour qu'il respecte un style unique et standardisé.

En Go, il n'y a qu'une seule façon d'écrire du code propre, et c'est l'outil qui s'en charge pour vous.

Le problème : un code difficile à lire

Pour bien comprendre l'intérêt de go fmt, mettons-nous en situation. Retournons à notre projet hello-go et modifions volontairement le fichier main.go pour qu'il soit mal formaté.

Copiez-collez cette version désordonnée. J'ai ajouté des espaces inutiles, des tabulations et des sauts de ligne incohérents.

package      main

    import "fmt"

func main()   {
fmt.Println(    "Hello, World!"    )
    }

Ce code est techniquement valide.

Si vous lancez go run main.go, il s'exécutera sans erreur. Cependant, il est très difficile à lire pour un humain.

Imaginez un projet de plusieurs milliers de lignes écrit de cette manière, ou pire, avec plusieurs styles différents mélangés. La maintenance deviendrait un cauchemar.

Comprendre la configuration par défaut de l'extension Go

L'extension est configurée pour exécuter automatiquement le formateur à chaque fois que vous sauvegardez un fichier.

Où voir la configuration par défaut de l'extension ?

Cliquez sur Go tout en bas puis Configure Go Language Based settings...

Vous aurez notamment :

"editor.formatOnSave": true

Cette ligne ordonne à VS Code : "Dès que l'utilisateur sauvegarde un fichier, exécute l'outil de formatage configuré pour ce langage".

Pour les fichiers Go, cet outil est goimports (qui inclut go fmt). C'est cette ligne qui rend le formatage automatique et transparent pour vous.

"editor.codeActionsOnSave": { "source.organizeImports": "explicit" }

Ceci est une instruction complémentaire qui s'exécute aussi à la sauvegarde. Elle dit spécifiquement à VS Code de lancer l'action qui organise les imports. C'est la partie qui correspond à la fonctionnalité de goimports :

  • Ajouter les imports manquants.

  • Supprimer les imports inutilisés.

  • Trier les imports par ordre alphabétique.

En résumé, formatOnSave s'occupe du style (espaces, indentation) et organizeImports s'occupe de la propreté de vos déclarations import.

"editor.insertSpaces": false

Cette règle est directement liée au style de Go. Elle indique à l'éditeur : "Quand l'utilisateur appuie sur la touche Tab, insère un vrai caractère de tabulation (\t), et non une série d'espaces".

C'est la convention stricte de go fmt, qui utilise des tabulations pour l'indentation. Cette ligne assure que votre éditeur et go fmt sont en parfait accord.

"go.toolsManagement.autoUpdate": true

Cette dernière ligne est une question de maintenance.

Elle autorise l'extension Go à mettre à jour automatiquement ses outils sous-jacents (comme gopls, le serveur de langage, ou dlv, le débogueur) en arrière-plan. Cela garantit que vous bénéficiez toujours des dernières améliorations et corrections de bugs sans avoir à vous en soucier.

Pour le moment mettez formatOnSave à false.

La solution : la magie de go fmt

Maintenant, nous allons demander à l'outil Go de nettoyer ce désordre pour nous.

  1. Ouvrez votre terminal intégré dans VS Code, en vous assurant d'être dans le dossier hello-go.

  2. Lancez la commande go fmt. Nous lui donnons le nom du fichier que nous voulons formater.

    go fmt main.go

  3. Observez le résultat. Appuyez sur Entrée. Il ne se passe rien dans le terminal, car go fmt est silencieux quand il réussit. Mais regardez votre fichier main.go dans l'éditeur. Il a été instantanément et automatiquement transformé en code bien formaté. 

Note : go fmt utilise des tabulations pour l'indentation, ce qui est la convention en Go. Votre éditeur peut les afficher comme un certain nombre d'espaces, mais ce sont bien des tabulations.

Réactivez formatOnSave à true.

Que fait go fmt exactement ?

Pour comprendre comment go fmt fonctionne, on peut imaginer qu'il déconstruit votre code en "briques de Lego" (sa structure logique) puis le reconstruit en suivant un plan d'assemblage parfait.

Techniquement, il analyse votre code, le transforme en une structure de données appelée Arbre Syntaxique Abstrait (AST), puis réimprime cet arbre en suivant des règles strictes.

Il s'occupe de :

  • L'indentation : tous les blocs de code (func, if, for, etc.) sont indentés avec des tabulations.

  • L'espacement : il ajuste les espaces autour des opérateurs (+, =, etc.), après les virgules, et entre les paramètres des fonctions.

  • Les sauts de ligne : il s'assure que les accolades sont placées correctement (accolade ouvrante sur la même ligne, accolade fermante sur une nouvelle ligne).

  • L'alignement : dans des cas plus avancés (comme les déclarations de struct), il aligne les champs et les commentaires pour une lisibilité maximale.

Ce que go fmt ne fait pas, c'est changer la logique de votre code. Il ne renomme pas vos variables et ne modifie pas le fonctionnement de votre programme. Son seul rôle est la présentation.

L'automatisation dans VS Code et goimports

Faire go fmt manuellement est rare. L'un des plus grands avantages de l'extension Go est qu'elle exécute un formateur à chaque fois que vous sauvegardez un fichier, grâce à l'option "editor.formatOnSave": true.

En réalité, l'extension utilise souvent un outil encore plus puissant que go fmt : goimports.

goimports fait tout ce que go fmt fait, PLUS la gestion de vos lignes import :

  • Il ajoute automatiquement les imports manquants.

  • Il supprime les imports que vous n'utilisez plus.

  • Il trie et groupe vos imports en deux blocs : bibliothèque standard, puis bibliothèques tierces.

L'expérience est si fluide que vous n'avez presque jamais à penser à vos imports ou à votre formatage. Vous écrivez votre code, vous sauvegardez, et tout est nettoyé pour vous.

Pourquoi est-ce si important ?

L'existence de go fmt a des conséquences profondes et extrêmement positives sur l'écosystème Go :

  • Zéro débat sur le style : c'est le bénéfice le plus évident. Les équipes ne perdent plus de temps ni d'énergie à débattre de la mise en forme du code.

  • Lisibilité accrue et universelle : tout le code Go, que vous le lisiez sur GitHub, dans un blog ou dans la bibliothèque standard, a la même apparence. Cela réduit considérablement la charge cognitive lorsque vous passez d'un projet à un autre.

  • Focalisation sur l'essentiel : en éliminant les soucis de présentation, go fmt permet aux développeurs de se concentrer sur ce qui compte vraiment : la logique du programme et la résolution des problèmes.

Adopter go fmt n'est pas une option, c'est une partie intégrante de l'écriture de code Go idiomatique. C'est un contrat social que tous les développeurs Go acceptent pour le bien de la communauté.
